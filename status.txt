Recent restructuring (this is not itself dated -- see docs/experiments/2026-06-raga-baseline-log.md for the dated history)
----------------------------------------------------------------------------------------------------------------------------

- Every script under tests/ (and the two at the repo root) that isn't an actual pytest test was renamed from test_*.py to run_*.py, so pytest no longer tries to collect them as tests. Only commentator/tests/test_pitch_contour.py is a real pytest test.
  - test_segment_lr_rf.py -> run_segment_lr_rf.py
  - test.py (root) -> run_pipeline_sanity_check.py
  - tests/test_mirdata.py -> tests/run_mirdata_check.py
  - tests/test_segment.py -> tests/run_segment_baseline_knn.py
  - tests/test.py -> tests/run_stage1_sanity_check.py
- Generated artifacts (feature CSVs, t-SNE plots, classifier reports) now write into outputs/ at the repo root instead of being scattered at the repo root and inside tests/. This is resolved relative to each script's own file location, not the caller's cwd, so it lands in the same outputs/ regardless of where a script is run from.
- Added tests/run_compmusic_check.py: a smoke test for the larger CompMusic "Indian Art Music Raga Recognition Dataset" (mirdata id compmusic_raga, Hindustani subset = HMD: 300 recordings, 30 ragas, 10 recordings/raga), which is the planned scale-up target beyond the current 108-track Saraga subset. Run successfully on 2026-08-16: all 300 tracks / 30 ragas confirmed, feeding the existing Stage-1 pipeline unchanged.
- commentator/io/loaders.py was renamed to commentator/io/saraga.py and joined by commentator/io/compmusic.py, one adapter per dataset sharing a common interface (see "Datasets available" below). The module-level Saraga function names are unchanged, so only import lines moved.
- Added tests/run_tonic_validation.py, which compares Stage-1's estimated tonic against the datasets' annotated tonic at both track and segment level. This is what surfaced the accuracy caveat below.

Plain-English summary of the repo
---------------------------------

The repo is centered on Hindustani raga analysis from pitch contours.
The main implementation lives under commentator/, with the analysis code split into tonic estimation, swara analysis, Stage-1 schema building, segment dataset construction, and feature extraction.
The docs/experiments folder records the baseline history and experiment decisions, including an archive of every historical t-SNE snapshot in docs/experiments/tsne/.
The tests/ folder contains evaluation scripts and feature inspection helpers (not, mostly, actual pytest tests -- see the renaming note above).
Generated artifacts (the CSV feature tables, t-SNE plots, classifier reports) live under outputs/.

What the current docs say
-------------------------

The baseline log says the current best classifier is Random Forest, because it reached the highest reported accuracy in the June 2026 comparison: 0.9051 segment-level accuracy, versus 0.8035 for logistic regression.
That result came from the CSV-based comparison flow in tests/classifier_compare.py (reports now written to outputs/classifier_compare/), not from the older KNN baseline.

DO NOT CITE 0.9051 (established 2026-08-16). That number comes from a leaky
evaluation and is not comparable to the grouped results elsewhere in the docs.

Cause: build_segment_feature_dataset wrote key_segment_features_table.csv as
raga_label plus bare numeric feature columns, with no track_id column. So
tests/classifier_compare.py's detect_group_column() found nothing and silently
fell back to train_test_split(..., stratify=y) -- a random split over segments.
Because segments are 30s windows at a 20s hop, consecutive segments overlap by
10s, so near-duplicate windows from the same recording landed in both train and
test: measured, 94.9% of test segments had an overlapping neighbour in train,
and all 13 tracks appeared on both sides. The script was honest about it (its
report printed "Group-aware split used: no; stratified segment split"); the
group column simply never reached the CSV.

FIXED (2026-08-16): the CSV now exports track_id, so detect_group_column() finds
it and GroupShuffleSplit engages. Re-running the identical flow with estimated
tonics gives LR 0.2402 and RF 0.2677, versus the leaky 0.8035 and 0.9051 -- i.e.
the leak accounted for essentially the whole figure. Note these sit below the
LeaveOneGroupOut numbers below because GroupShuffleSplit holds out ~4 whole
recordings at once and trains on ~9, without averaging over folds;
run_segment_lr_rf.py's numbers are the ones to quote.

The correct grouped numbers, from run_segment_lr_rf.py with LeaveOneGroupOut
over the same 1809 segments / 71 features (matching the ~61.5% ceiling recorded
in the 2026-06-22 and 06-23 log entries):

                        estimated tonic      annotated tonic
    LR  track-level         0.615                0.615
    LR  segment-level       0.375                0.520
    RF  track-level         0.615                0.538
    RF  segment-level       0.384                0.441

A separate, real issue (do not conflate it with the leakage above): Stage-1
estimates the tonic per 30s window, and tests/run_tonic_validation.py shows
50.2% of those segments get a pitch-class-wrong tonic, i.e. their swaras are
assigned against the wrong Sa. Both datasets ship an annotated tonic that the
pipeline ignored until now; run_segment_lr_rf.py --annotated-tonic uses it.
Doing so raises segment accuracy for both classifiers, and notably flips the
ranking: LR (0.520) overtakes RF (0.441), consistent with RF's earlier edge
coming partly from fitting track-specific estimator artifacts.

The current entrypoint in use
------------------------------

The active script is run_segment_lr_rf.py at the repo root (renamed from test_segment_lr_rf.py).

How the current pipeline works when running run_segment_lr_rf.py
------------------------------------------------------------------

1. The script starts in run_segment_lr_rf.py and initializes the Saraga dataset through commentator/io/saraga.py via initialize_saraga(DATA_HOME).
2. For each chosen track, it gets a PitchContour with get_pitch_for_track(...), which wraps the mirdata pitch data in commentator/core/pitch_contour.py.
3. The segment builder in commentator/analysis/segment_dataset.py infers track duration from pitch_obj.times, then creates 30-second windows with a 20-second hop and a 15-second minimum duration.
4. Each window is sliced into a smaller PitchContour with slice_pitch_contour(...).
5. The slice is passed into build_stage1_schema(...) from commentator/analysis/stage1_schema.py.
6. build_stage1_schema(...) calls analyze_pitch_musically(...) in commentator/analysis/pipeline_one.py.
7. analyze_pitch_musically(...) runs the Stage-1 chain:
   - tonic estimation in commentator/analysis/tonic_estimator.py
   - tonic normalization in commentator/analysis/tonic_estimator.py
   - swara assignment and swara summary in commentator/analysis/swara_analyzer.py
   - a short textual comment from the same swara/tonic helpers
8. extract_raga_features_from_stage1(...) in commentator/analysis/raga_features.py converts that Stage-1 dict into a numeric feature vector.
9. That feature vector is built from tonic, swara, range, histogram, movement, stability, and pattern features, then reduced again by apply_feature_subset(...).
10. build_segment_feature_dataset(...) collects all valid segments into X, feature_names, and records, and also writes outputs/key_segment_features_table.csv plus an outputs/tsne_segments_*.png (filename encodes raga count, feature count, and segment window) as side artifacts.
11. Back in run_segment_lr_rf.py, failed segments are dropped, y labels and groups are built from raga_label and track_id, and the evaluation uses LeaveOneGroupOut so the held-out unit is always an entire track.
12. The script then fits and evaluates two pipelines:
   - Logistic Regression: SimpleImputer -> StandardScaler -> LogisticRegression
   - Random Forest: SimpleImputer -> RandomForestClassifier
13. For each held-out track, segment predictions are majority-voted into a track-level prediction.
14. The script prints track accuracy, segment accuracy, a confusion matrix, and a classification report for each classifier.

Bottom line
-----------

If you want the best honest (grouped) result so far, it is Logistic Regression with --annotated-tonic: 0.520 segment-level, 0.615 track-level. Random Forest only looks better under the leaky split -- see the caveat above.
If you want the current runnable test entrypoint, use run_segment_lr_rf.py.
If you want the older baseline, that was tests/run_segment_baseline_knn.py (formerly test_segment.py) with KNN.
If you want to check how much the Stage-1 tonic estimate can be trusted, run tests/run_tonic_validation.py.
If you want the larger CompMusic/Dunya scale-up dataset, tests/run_compmusic_check.py works and has been run: 300 Hindustani tracks, 30 ragas, 10 per raga, feeding the existing Stage-1 pipeline unchanged.

Datasets available
------------------

Two datasets, each with an adapter in commentator/io/ exposing the same interface
(name / list_tracks() / get_pitch(track_id) / get_tonic(track_id)), so pipeline
code can be pointed at either without changes:

- SaragaHindustani (commentator/io/saraga.py) -- 108 tracks, but only 6 ragas
  have >=2 usable tracks; the experiments use a 13-track subset. DATA_HOME is
  /home/thesidpai/mir_projects/data.
- CompMusicHindustani (commentator/io/compmusic.py) -- the CompMusic HMD subset:
  300 recordings, 30 ragas, exactly 10 per raga. Read directly off the extracted
  tree at data/compmusic_raga/RagaDataset/Hindustani/, because mirdata's
  compmusic_raga index v1.0 covers only the 477 Carnatic recordings and exposes
  zero Hindustani tracks. Construct with download=True to fetch the ~3.4 GB
  features archive (free, no credentials; audio is separate and restricted).

Both datasets ship an annotated tonic, which the Stage-1 pipeline does not
currently consume -- see the caveat above.
